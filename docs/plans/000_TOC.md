### Executive Overview & Migration Strategy

The primary objective of the **dpMaps** architecture is **operational self-sufficiency**: ensuring Ride continues uninterrupted dispatch, routing, and passenger search operations if commercial mapping vendors (Barikoi, Google) experience outages, introduce prohibitive pricing, or terminate contracts. Cost is a secondary consideration; deterministic availability, data sovereignty, and clean-room provenance are paramount.

The implementation is executed across **5 chronological phases** and **16 technical stages**, governed by **Two Independent Administrative Toggles** in `system_config`:
1. `routing_provider_mode`: `0 (off)` $\rightarrow$ `1 (shadow)` $\rightarrow$ `2 (primary)` $\rightarrow$ `3 (sole)`
2. `search_provider_mode`: `0 (off)` $\rightarrow$ `1 (shadow)` $\rightarrow$ `2 (primary)` $\rightarrow$ `3 (sole)`

### Architectural Invariants & Non-Negotiable Rules

1. **IP Clean-Room Isolation Boundary:**
   Zero vendor-returned strings, place IDs, geometries, or coordinates may ever be stored on disk, logged in telemetry, or indexed into `public_pois`. All learning originates exclusively from first-party signals: raw user keystrokes typed prior to autocomplete, physical driver GPS exit breadcrumbs, post-trip passenger confirmations, and clean-room Pin Tool field surveys.
2. **Deterministic Hot-Reloadable State Machine:**
   State transitions between `off`, `shadow`, `primary`, and `sole` are controlled via database configuration (`system_config`), taking effect in `<1 second` across the cluster without container restarts or service interruptions.
3. **Objective Numeric Gates Over Calendar Dates:**
   Cutover decisions are dictated strictly by multi-week sustained numeric performance thresholds (e.g., Gate 1 & Gate 2), never by arbitrary calendar dates.
4. **Permanent Separation of ODbL & Proprietary Data:**
   OpenStreetMap data (used for OSRM graph contraction and Planetiler vector tiles) remains in an isolated open-source attribution layer. Proprietary POI databases (`public_pois`), user private places, and trip ledgers are never merged into OSM derivative files, preserving 100% first-party intellectual property ownership.
